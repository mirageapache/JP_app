> 版本：v0.4（v0.2 依審查問題清單 `plan-review-questions.md` 修訂；v0.3 改用 Firebase 同步；v0.4 第二輪審查修訂）

## 1. 專案概述

### 1.1 目標

打造一個以 iPhone 為主要使用裝置的日語學習 PWA，核心特色是**螢幕手寫練習**，並逐步擴充為涵蓋 N5～N1 的完整學習工具。

### 1.2 使用者與情境

| 項目 | 說明 |
|---|---|
| 使用者 | 以自己為主，不對外公開 |
| 主要裝置 | iPhone（Safari → 加入主畫面），支援 iOS 17 以上 |
| 目前程度 | 50 音大多會念但不夠熟練、不太會寫；學過基本文法與單字 |
| 使用情境 | 通勤、零碎時間，每天 10～20 分鐘；通勤時以點選式練習為主，坐下來時才手寫 |
| 網路 | 離線可用；有網路時自動同步到雲端 |
| 時區 | 固定以台灣時間（UTC+8）計算，每日 0 點為日界線 |

### 1.3 範圍

**範圍內**
- 50 音學習：辨識練習、手寫練習（含筆順、筆畫比對）
- 單字學習與間隔重複複習（SRS）
- 文法學習與小測驗
- 進度統計
- 資料同步與備份：Firebase 帳號登入，學習紀錄自動同步到雲端，可跨裝置使用；匯出／匯入 JSON（存到「檔案」App）作為備案
- 先完成 N5/N4 內容，架構需能擴充至 N1

**範圍外（目前不做）**
- 自行架設後端伺服器、BFF、Cloud Functions
- App 未開啟時的背景同步（iOS PWA 技術上做不到）
- 商業化、上架 App Store / Google Play
- 自由手寫辨識（空白畫布辨識任意字）
- 多語系介面
- 繁體字形與日本新字體的對照功能（日後再評估）

### 2.2 非功能需求

- **支援範圍**：iOS 17 以上的 Safari 與主畫面 App；不為更舊版本做降級處理
- **離線優先**：所有學習內容與進度存在本機，無網路仍可完整使用
- **效能**：手寫時筆跡延遲不可察覺（目標 < 16ms/事件）；首頁載入 < 2 秒（Firebase 等非核心模組延遲載入）
- **資料安全**：
  - 進度資料不得因更新內容而損毀（見 5.1 穩定 ID）
  - 本機資料遺失時，不得覆蓋或刪除雲端資料（見 7.5）
  - 使用者只能存取自己的雲端資料（Firestore 安全規則，見 7.4）
- **隱私**：一般練習不保存筆跡座標，只有開啟調校模式時才保存（見 6.1）
- **日文顯示**：所有日文內容一律標示 `lang="ja"`，確保 iOS 使用日文字型顯示漢字（見 6.6）
- **可擴充**：新增等級只需新增內容包，不改程式
- **可維護**：TypeScript；核心演算法（SRS、手寫比對、同步合併）與 Firestore 安全規則有測試；資料庫 schema 變更皆有遷移函式；App 內有除錯面板可在 iPhone 上直接查看錯誤

## 3. 技術選型

| 層級 | 選擇 | 理由 |
|---|---|---|
| 框架 | Vue 3 + TypeScript + Vite | 最熟悉的技術 |
| PWA | `vite-plugin-pwa`（Workbox），`registerType: 'prompt'` | 離線快取、Service Worker、Manifest；有新版本時提示使用者更新。App Shell 預快取；內容包改用執行期快取（CacheFirst），避免每次內容更新都重新下載全部 |
| 狀態 | Pinia | 只作為設定與畫面狀態的讀取快取，資料以 Dexie 為準 |
| UI | Vant 4 或 Konsta UI | **P0 各做一頁試用後決定** |
| 本機資料庫 | IndexedDB + Dexie | PWA 內建，API 友善；App 的主要資料庫 |
| 雲端同步 | Firebase Auth + Cloud Firestore（`firebase/firestore/lite`） | 登入狀態由 SDK 自動維護；免費方案足夠個人使用；不需自行架設後端。同步模組以動態 `import()` 延遲載入 |
| SRS | `ts-fsrs` | FSRS 演算法的 TS 實作；固定參數並記錄版本 |
| 手寫 | Canvas + Pointer Events + 自寫比對 | 無需 ML；比對演算法參考 Hanzi Writer（MIT） |
| 筆順資料 | KanjiVG（SVG） | 涵蓋假名與漢字，含筆畫路徑 |
| 發音 | Web Speech API（`ja-JP`） | iOS 內建，零成本；單字送假名讀音避免誤讀 |
| 測試 | Vitest | 與 Vite 整合；手寫比對以真實筆跡樣本做回歸測試 |
| 除錯 | App 內除錯面板（eruda 或自製） | 開發機為 Windows，無法用 Safari 遠端除錯 iPhone；錯誤需能在手機上直接查看 |
| 託管 | Cloudflare Pages | 免費、自動 HTTPS |
| 內容建置 | Python（`tools/`） | KanjiVG、JMdict 處理；SudachiPy 或 fugashi 產生讀音；OpenCC 轉繁體 |

> **關於資料庫**：PWA 無法直接使用 SQLite，只能使用瀏覽器內建的 IndexedDB（透過 Dexie 操作）。資料量（數千張卡片 + 複習紀錄）遠在其能力範圍內。代價是資料受瀏覽器的清除規則管理，保存比原生 App 脆弱，因此需要雲端同步（見第 7 章）。若日後改包 Capacitor，可再遷移至 SQLite。

> **關於雲端**：v0.2 原規劃以 Google Drive 存放備份檔，但純前端的 access token 約 1 小時過期，每次備份都需使用者點擊重新授權，且需複雜的防覆蓋流程。v0.3 改用 Firebase：登入狀態可長期維持、紀錄逐批自動上傳、只增不改，因此不再採用 Google Drive。

> **關於後端**：不採用 BFF。Firebase 本身設計為前端直接存取，加上 BFF 不會解決任何現有問題（理由見 7.2）。

## 4. 系統架構

```
┌─────────────────────────────────────────────────────┐
│  PWA（Vue 3 + TypeScript）—— 全部運行於裝置端          │
│                                                     │
│  View 層     Kana │ Vocab │ Grammar │ Quiz │ Stats  │
│  Store 層    Pinia（畫面狀態、設定的讀取快取）         │
│  Service 層  每日佇列 │ SRS 引擎 │ 手寫比對 │ TTS │ 同步 │
│  Data 層     Dexie（IndexedDB）—— 主要資料庫          │
│  內容層      靜態 JSON 內容包（隨 App 快取）           │
│  Service Worker：App Shell 與內容包離線快取           │
└───────────────────────┬─────────────────────────────┘
                        │ 有網路時，背景同步學習紀錄
              ┌─────────▼──────────────────┐
              │  Firebase                   │
              │  Auth（登入）               │
              │  Firestore（紀錄批次、設定）│
              └────────────────────────────┘
```

**設計原則**
1. **內容與進度分離**：內容（唯讀、隨版本更新）與進度（使用者資料）是兩個獨立的東西，以穩定 ID 連結
2. **紀錄只增不改（append-only）**：複習紀錄與卡片事件是唯一事實來源；`cards` 只是可由紀錄重建的快取，同步與合併因此只需取聯集
3. **一個學習項目，多張技能卡**：同一項目的不同技能（例如讀與寫）各自排程
4. **不自架後端**：雲端只用 Firebase 的託管服務，降低維運成本，符合自用定位
5. **離線優先**：學習時只讀寫本機 Dexie，同步失敗不影響使用
6. **資料以 Dexie 為準**：Pinia 只做讀取快取；寫入時先寫 Dexie，成功後再更新 Pinia

## 5. 資料設計

### 5.1 穩定 ID 規則

所有學習項目有永久不變的 ID，進度只存 ID，不存內容本身。**ID 不含 JLPT 等級**（等級只是內容欄位，可能隨清單調整而改變），假名直接使用字元本身，避免羅馬字撞名（じ/ぢ、ず/づ）。

**學習項目 ID**

| 類型 | 格式 | 範例 |
|---|---|---|
| 假名 | `kana:<字元>` | `kana:あ`、`kana:ぢ`、`kana:きゃ`、`kana:ツ` |
| 單字 | `vocab:<JMdict ent_seq>` | `vocab:1358280` |
| 文法 | `grammar:<英文代稱>` | `grammar:te-kudasai` |
| 漢字 | `kanji:<字元>` | `kanji:日` |

**卡片 ID = 學習項目 ID + `#` + 技能**

| 類型 | 技能 | 說明 | 卡片 ID 範例 |
|---|---|---|---|
| 假名 | `read` | 看字讀音（辨識練習） | `kana:あ#read` |
| 假名 | `write` | 看音寫字（手寫練習）；拗音（きゃ 等）不建立 `write` 卡，小寫假名（ゃ、ゅ、ょ、っ）作為獨立項目練寫 | `kana:あ#write` |
| 單字 | `recognize` | 看日文想中文意思 | `vocab:1358280#recognize` |
| 單字 | `produce` | 看中文想日文 | `vocab:1358280#produce` |
| 單字 | `listen` | 聽讀音想中文意思 | `vocab:1358280#listen` |
| 文法 | `understand` | 看句子理解意思 | `grammar:te-kudasai#understand` |
| 文法 | `apply` | 挖空填入 | `grammar:te-kudasai#apply` |
| 漢字 | `read`、`write` | 讀音、手寫 | `kanji:日#write` |

> - 內容修正（改中文意思、改例句）不會影響進度；**已發佈的 ID 絕不重用或改名**
> - 內容下架時不刪除，改標 `deprecated: true`，對應卡片停止出題但保留紀錄
> - 日後新增技能不影響既有紀錄

### 5.2 內容包結構

```
public/content/
├─ manifest.json          # 版本號、各內容包清單
├─ kana.json              # 含學習順序、行別、筆畫版本
├─ strokes/               # 由 KanjiVG 預先處理的筆畫資料（含手動補充的變體）
├─ topics.json            # 單字主題分類定義
├─ n5/
│  ├─ vocab.json
│  ├─ grammar/*.json
│  └─ kanji.json
├─ n4/ ...
└─ n3/ ... n1/（日後擴充）
```

**共用欄位**
- `order`：主線學習順序（SRS 依此挑選新卡）
- `deprecated`：是否已下架
- 所有日文文字（單字、例句）一律使用**分段格式**，一份資料同時承載純文字、讀音標注與文法目標標記，避免多份表示不同步：
  `[{ "text": "食", "ruby": "た" }, { "text": "べる" }]`、`[{ "text": "書い" }, { "text": "てください", "target": true }]`
  純文字由分段組合而得，不另存 `ja` 字串

**假名範例**
```json
{
  "id": "kana:そ",
  "script": "hiragana",
  "row": "さ行",
  "order": 15,
  "romaji": "so",
  "strokeVariants": [
    { "id": "1", "label": "一筆寫法", "default": true },
    { "id": "2", "label": "兩筆寫法" }
  ]
}
```

**單字範例**
```json
{
  "id": "vocab:1358280",
  "level": "N5",
  "order": 123,
  "kana": "たべる",
  "kanji": "食べる",
  "usuallyKana": false,
  "altForms": [],
  "segments": [{ "text": "食", "ruby": "た" }, { "text": "べる" }],
  "pos": "動詞（一段）",
  "conjugation": "ichidan",
  "meaning": ["吃"],
  "tags": ["飲食"],
  "examples": [
    {
      "segments": [{ "text": "りんごを" }, { "text": "食", "ruby": "た" }, { "text": "べる。" }],
      "zh": "吃蘋果。"
    }
  ],
  "deprecated": false
}
```

**文法範例**
```json
{
  "id": "grammar:te-kudasai",
  "level": "N5",
  "order": 12,
  "lesson": 14,
  "title": "〜てください",
  "connection": "動詞て形 + ください",
  "explanation": "用於禮貌地請求對方做某事。",
  "examples": [
    {
      "segments": [
        { "text": "ここに" }, { "text": "名前", "ruby": "なまえ" }, { "text": "を" },
        { "text": "書", "ruby": "か" }, { "text": "い" }, { "text": "てください", "target": true }, { "text": "。" }
      ],
      "zh": "請在這裡寫名字。"
    }
  ],
  "exercises": []
}
```

> - 單字欄位：`kanji` 為主要寫法、`kana` 為主要讀音；`usuallyKana` 為 true 時以假名顯示並以假名為 `produce` 卡正解；`altForms` 列出其他可接受的寫法（例如 玉子／卵），拼字題一併接受
> - 例句分段中 `target: true` 標記文法目標片段，供挖空題使用
> - `exercises` 的 schema 於 P3 開始前定義

### 5.3 本機資料表（Dexie）

| 表 | 主要欄位 | 說明 | 同步到雲端 |
|---|---|---|---|
| `cards` | `id`（卡片 ID）、`itemId`、`skill`、`type`、FSRS 狀態（due, stability, difficulty, reps, lapses, state…） | **快取**，可由 `reviewLogs` + `cardEvents` 重建 | 否（下載後重建） |
| `reviewLogs` | `uuid`、`cardId`、`rating`、`reviewedAt`、`durationMs`、`mode`、`deviceId` | SRS 評分紀錄，**只增不改** | 是 |
| `cardEvents` | `uuid`、`cardId`、`type`（markKnown / suspend / unsuspend / reset / paramsChanged）、`payload`、`at`、`deviceId` | 非評分操作，**只增不改**；`markKnown` 以卡片（含技能）為單位；`paramsChanged` 記錄 FSRS 參數變更，重放時依當時生效的參數計算 | 是 |
| `handwritingLogs` | `uuid`、`cardId`、`variantId`、`score`、`strokeResults`、`at` | 手寫練習紀錄；`strokeResults` 只存每一筆的判定結果，**不存座標** | 是 |
| `quizLogs` | `uuid`、`itemId`、`quizType`、`correct`、`at` | 測驗紀錄，不影響 FSRS | 是 |
| `contentReports` | `uuid`、`itemId`、`field`、`note`、`at`、`resolved` | 內容錯誤回報 | 是 |
| `strokeSamples` | `uuid`、`cardId`、`variantId`、難度、`pointerType`、筆跡座標、判定結果、人工標記、`recordedAt` | **僅調校模式**時寫入 | 否（另行匯出） |
| `settings` | `key`、`value`、`scope`（account / device）、`updatedAt` | 設定的唯一來源（Pinia 僅快取）；`updatedAt` 只在使用者實際修改時更新，初始化預設值不算 | 僅 `scope = account` |
| `errorLogs` | `id`、`level`、`message`、`stack`、`at` | 除錯面板用，保留最近 N 筆 | 否 |
| `syncMeta` | `uid`、`deviceId`、`lastPulledAt`、`lastPushedAt`、`lastError` | 本機同步狀態 | 否 |

**Schema 遷移**
- Dexie 每次 schema 變更都升版本號並撰寫遷移函式
- 同一組遷移函式也用於匯入舊版 JSON 檔與下載舊版雲端 chunk（依 `schemaVersion` 逐版升級）

**同步欄位**
- 標示「同步到雲端：是」的紀錄表都加上 `syncedAt` 欄位（`null` 代表尚未上傳），並建立索引以便快速找出待上傳紀錄（見 7.5）

**設定的範圍**

| `scope` | 項目 | 同步 |
|---|---|---|
| `account` | 每日新卡數、每日目標、讀音顯示、筆畫版本選擇、`listen` 技能開關、通勤模式預設值 | 是，以 `updatedAt` 較新者為準 |
| `device` | 調校模式開關、除錯面板開關、`deviceId`、上次同步狀態 | 否 |

## 6. 核心模組設計

### 6.1 手寫比對引擎（本專案最重要的模組）

**資料準備（離線預處理，Python 腳本）**
- 從 KanjiVG 取出假名與目標漢字的 SVG
- 解析每一筆畫路徑，取樣成固定點數的折線（座標系 109×109）
- KanjiVG 每個字只有一種寫法；常見的其他寫法（例如 そ、り 的一筆／兩筆）以手動方式補充變體資料
- 濁音、半濁音（が、ぱ）：P0 確認 KanjiVG 是否有獨立檔案；若無，由基本字的筆畫加上濁點／半濁點筆畫組合而成
- 拗音（きゃ）不做手寫題；小寫假名（ゃ、ゅ、ょ、っ）作為獨立項目，使用 KanjiVG 的小寫字形
- 輸出成 `strokes/*.json`，App 不需在執行期解析 SVG

**書寫區**
- 畫面固定一個書寫格（田字格），畫布座標直接線性映射到 109×109
- 描摹、提示、空白三種難度共用同一座標系，不對單一筆畫或整個字做外框正規化

**即時比對流程**
1. 以 `PointerEvent` 收集筆畫；支援時使用 `getCoalescedEvents()` 取得完整軌跡，不支援時退回一般 `pointermove`
2. 使用者每抬筆一次，視為完成一筆
3. 將該筆畫重取樣為 N 點（暫定 32）
4. 與「預期的第 k 筆」比對，比對方式參考 Hanzi Writer：
   - **位置／形狀**：依順序逐點的平均距離，以及形狀距離（Fréchet distance）
   - **方向**：依順序逐點比對本身即可偵測反向書寫（不使用單一起訖向量，避免「゜」等圓形與短點畫誤判），輔以分段方向比對
   - **起訖點**：起點與終點各自與標準筆畫的距離
   - **長度比例**：與標準筆畫長度比在合理範圍
5. 若不符合第 k 筆，再與其他尚未書寫的筆畫比對；若更接近其中某筆，判定為**順序錯誤**
6. 判定結果：通過 / 位置偏差 / 方向錯誤 / 順序錯誤，並給出視覺回饋
7. 全部筆畫完成後，算出整體分數，並據此建議 SRS 評分

**判錯後的流程與評分**
- 某一筆判錯：該筆消失，重寫；同一筆連錯 3 次時顯示該筆的提示動畫，之後仍需寫對才繼續
- 整字放棄（按「跳過」）：記為失敗
- 整字完成後轉換為 FSRS 評分建議（使用者可手動改）：

| 結果 | 建議評分 |
|---|---|
| 全部筆畫一次通過，且總時間低於該字的平均時間 | 簡單 |
| 全部筆畫一次通過 | 良好 |
| 有重寫，但總重寫次數 ≤ 2 | 困難 |
| 重寫次數 > 2、有筆畫看過提示，或放棄 | 重來 |

**筆畫版本**
- 有多種寫法的字，練習畫面提示「此字有其他常見寫法」
- 使用者可在該字的練習畫面或設定頁選擇習慣的版本，之後以該版本判定

**難度設定**：門檻值可依難度調整（描摹寬鬆、空白嚴格）；依 `pointerType` 區分手指與 Apple Pencil，手指的門檻乘上放寬係數；門檻先以經驗值設定，實測後微調。

**調校模式**
- 設定頁中的開關，預設關閉
- 開啟時，每次書寫的筆跡座標存入 `strokeSamples`，並出現「判定有誤」按鈕可標記誤判樣本
- 調校頁可匯出筆跡樣本，作為 Vitest 回歸測試的資料（`tests/fixtures/strokes/`）
- 刪除機制：
  - 調校頁顯示樣本數量與佔用空間
  - 可刪除單筆樣本、某個字的所有樣本、全部樣本（刪除全部前顯示確認畫面）
  - 關閉調校模式時，詢問是否一併刪除已保存的筆跡
- 一般練習**不保存筆跡座標**，練習結束後筆跡只留在記憶體中，關閉畫面即消失

**畫布細節（iOS）**
- `touch-action: none`、`user-select: none`、`-webkit-touch-callout: none`
- 畫布與螢幕邊緣保留邊距，避免觸發邊緣滑動返回手勢
- 依 `devicePixelRatio` 調整畫布解析度
- 支援 Apple Pencil 與手指，不特別處理手掌誤觸（先不做）

### 6.2 SRS 引擎與每日佇列

**排程**
- 採用 `ts-fsrs`，初期使用預設參數；參數與套件版本記錄在 `cardEvents`（`paramsChanged`），重放時依當時生效的參數計算，因此日後可用自己的複習紀錄跑 FSRS 優化器調整參數，不影響重建一致性
- 每個學習項目依技能拆成多張卡片（見 5.1），各自排程
- 評分：重來 / 困難 / 良好 / 簡單；手寫題與辨識題由結果自動建議評分
- 卡片狀態由 `reviewLogs` + `cardEvents` 重建（同步合併後使用）
- 弱點分數（由 `handwritingLogs` 計算）**只用於弱點專練與統計頁**，不影響每日佇列
- 測驗結果寫入 `quizLogs`，**不影響 FSRS**
- 自由瀏覽時的練習（非每日佇列）只寫 `handwritingLogs`，**不寫 `reviewLogs`**，避免提前複習打亂排程

**每日佇列**

| 項目 | 規則 |
|---|---|
| 新卡上限 | 各類型分開計，以**學習項目**計數；預設假名 5、單字 3、文法 1，可在設定調整（假名學完後可考慮將單字調高） |
| 技能錯開 | 同一項目的技能卡不同天出現：先出辨識類（`read`、`recognize`、`understand`），該卡首次複習通過後，才加入產出類（`write`、`produce`、`apply`）與 `listen` |
| 每日目標 | 預設 20 分鐘；達成時提示「今天的目標完成了」，可繼續練習（軟性上限） |
| 新卡自動暫停 | 到期的複習卡超過 100 張時，當天暫停出新卡，先消化複習 |
| 出題順序 | 到期複習卡（越久沒複習的越先）→ 新假名 → 新單字 → 新文法 |
| 多學一點 | 提供「今天想多學一點」按鈕，再加入一批新卡 |
| 通勤模式 | 「今天先不手寫」開關：到期的 `write` 卡延後到當天稍晚，不算逾期、不影響評分；只出點選式的卡 |
| 日界線 | 固定以台灣時間（UTC+8，`Asia/Taipei`）每日 0 點為界，不隨裝置時區變動 |

**學習順序（新卡出現的路徑）**

| 類型 | 主線順序 | 其他模式 |
|---|---|---|
| 假名 | 依行：あ行 → か行 → …… → わ行，再來濁音、半濁音、拗音；平假名與片假名同屬「假名」類型 | — |
| 單字 | 依等級（N5 → N4），同等級內依常用度（以 JMdict 的常用度標記排序） | **主題模式**：同一批卡片改以主題分類呈現，使用者可選擇先學某個主題 |
| 文法 | 依《大家的日本語 初級 I／II》的課次（初級 I 約對應 N5、初級 II 約對應 N4） | 可選擇課次 |

- SRS 每日佇列以外的內容（50 音表、單字列表、文法說明、筆順動畫）**全部開放自由瀏覽與練習**
- 使用者選擇主題或課次後，新卡改從該主題／課次中依主線順序挑選

**標記已會**
- 以**卡片（含技能）**為單位，可依技能批次標記，例如「整行假名的 `read` 標記已會、`write` 繼續練」，符合「會念但不會寫」的情況
- 寫入 `cardEvents`（`markKnown`，`payload` 含模式）
- 預設行為是**暫停排程**（等同 `suspend`），不會再出現在每日佇列，避免大量「已會」卡在幾週內一起回來
- 另提供「偶爾複習」模式：以較長的初始穩定度（約 90 天）排入 FSRS，之後以長間隔出現

### 6.3 發音

- 優先使用 iOS `speechSynthesis` 的 `ja-JP` 語音，`utterance.lang` 設為 `ja-JP`
- 首次播放須由使用者點擊觸發；`listen` 卡顯示時能否自動播放，於 P0 實測（iOS 通常在頁面有過互動後即允許），不行則顯示播放按鈕
- `listen` 技能可在設定中關閉；P2 驗證 TTS 品質後再決定預設開啟與否
- 單字發音送 `kana` 欄位而非漢字，避免 TTS 誤讀（今日、行った、方……）
- 例句與聽力題需抽查讀音；誤讀嚴重者改用預錄或預先產生的音檔（屬內容包的一部分）

### 6.4 假名模組

- 分行學習（あ行、か行……）、濁音、半濁音、拗音
- 練習模式：
  - **辨識**：看字選讀音（點選作答，通勤用）— P1b
  - **看字寫字**：筆順動畫 + 描摹／空白 — P1a
  - **看音寫字**：聽音或看羅馬字後手寫 — P1a（自由練習）、P1b（進入每日佇列）
  - **易混淆對照**：シ/ツ、ソ/ン、ぬ/め 等 — P1.5
  - **弱點專練**：依弱點分數排序 — P1.5
- 平假名與片假名在 SRS 中同屬「假名」類型；開發上先做平假名（P1a／P1b），片假名於 P1.5 加入
- 自由練習只寫 `handwritingLogs`，不影響 FSRS

### 6.5 測驗

- 題型：選擇、拼字（輸入假名）、聽力選擇、手寫
- 題目由內容包資料自動產生：
  - 單字 → 意思選擇題；干擾選項取同詞性、同等級的單字
  - 文法例句 → 挖空題；挖空位置取自例句分段中 `target: true` 的片段
- 拼字題使用系統鍵盤；網頁無法得知裝置裝了哪些鍵盤，改為第一次進入拼字題時顯示安裝 iOS 日文鍵盤的說明，並在作答內容不含任何假名時再次提示
- 答案比對前先正規化：平假名／片假名、長音「ー」、小寫假名（っ、ゃ……）、全形／半形
- 結果寫入 `quizLogs`，不影響 FSRS 排程

### 6.6 日文顯示規範

- 所有日文內容一律透過共用元件輸出，元件固定加上 `lang="ja"`，確保 iOS 以日文字型顯示漢字（避免「直」「骨」「写」等字顯示成中文字形）
- 讀音標注（振り仮名）以 `<ruby>` 呈現，**預設顯示**，使用者可在設定中切換顯示／隱藏

### 6.7 內容錯誤回報

- 單字、例句、文法畫面提供「回報錯誤」按鈕，可選擇錯誤欄位（意思、讀音、例句翻譯……）並附註
- 回報存入 `contentReports` 並同步到 Firestore，可直接在 Firebase 後台（電腦上）查看，作為修正內容包的依據；設定頁另提供匯出清單

## 7. 同步與備份

### 7.1 需求

- 學習紀錄自動同步到雲端，不需要使用者手動備份
- 換手機、刪除主畫面 App 或資料被清除後，登入即可還原
- 同一帳號可在多台裝置使用（例如 iPhone 與 iPad），紀錄自動合併
- 本機資料遺失時，不得覆蓋或刪除雲端資料
- 保留不依賴雲端的備案：匯出／匯入 JSON（存到「檔案」App）

### 7.2 架構

| 項目 | 設計 |
|---|---|
| 服務 | Firebase（Spark 免費方案，不需綁信用卡） |
| 登入 | Firebase Auth：**預設電子郵件 + 密碼**（流程在 App 內完成，不需彈出視窗）；Google 登入為選項，P0 驗證可行後才開放 |
| 雲端資料庫 | Cloud Firestore，前端使用 `firebase/firestore/lite`（體積較小；離線由 Dexie 負責，不使用 Firestore 的離線快取） |
| 本機資料庫 | Dexie 仍為主要資料庫；學習時只讀寫 Dexie，同步在背景進行 |
| 後端 | 不自行架設伺服器、不使用 BFF 或 Cloud Functions |
| 託管 | 前端維持 Cloudflare Pages；需將正式網域加入 Firebase Auth 的授權網域；預覽部署的子網域是否需逐一加入，P0 確認 |
| 載入 | Firebase 相關模組以動態 `import()` 延遲載入，只在登入或同步時才下載，不影響首頁載入時間 |

> **不採用 BFF 的理由**：Firebase 的設計就是讓前端直接存取，登入狀態由 SDK 自動維護，權限由安全規則控管。加上 BFF 不會解決任何現有問題，反而增加伺服器、費用（Cloud Functions 需升級為付費方案）與維運負擔。日後若需要在 App 內呼叫需要保密金鑰的服務（例如 AI API），再評估加入。

### 7.3 Firestore 資料結構

```
users/{uid}/
├─ chunks/{chunkId}        # 紀錄批次，每次同步新增一份，只增不改
│    deviceId, createdAt (serverTimestamp), schemaVersion,
│    reviewLogs[], cardEvents[], handwritingLogs[], quizLogs[], contentReports[]
└─ settings/main           # 僅 scope = account 的設定，每個 key 各帶 updatedAt，較新者為準
```

- **紀錄打包上傳**：每次同步把尚未上傳的紀錄打包成一份 `chunk` 文件，而不是每筆紀錄一份文件。可大幅減少讀取次數，避免換手機時一次讀回大量文件超過免費額度（每日約 5 萬次讀取）
- 單一文件上限 1 MiB；待上傳紀錄過多時拆成多份 chunk
- `cards`、`strokeSamples`、`syncMeta` 不上傳（與第 5.3 節的「同步到雲端」欄位一致）

### 7.4 安全規則

```
match /users/{uid}/{document=**} {
  allow read: if request.auth.uid == uid;
}
match /users/{uid}/chunks/{chunkId} {
  allow create: if request.auth.uid == uid
    && request.resource.data.createdAt == request.time   // 時間由伺服器決定，增量下載才可信
    && request.resource.data.deviceId is string
    && request.resource.data.schemaVersion is int;
  allow update: if false;          // 只增不改
  allow delete: if request.auth.uid == uid;  // 僅供「刪除帳號與雲端資料」使用
}
match /users/{uid}/settings/{doc} {
  allow write: if request.auth.uid == uid;
}
```

- Firebase 設定值會公開在前端程式碼中，資料安全完全依賴安全規則
- 安全規則需以 Firebase Emulator 撰寫測試，確認無法讀寫他人資料

### 7.5 同步流程

**上傳（本機 → 雲端）**
- 各紀錄表加入 `syncedAt` 欄位，`null` 代表尚未上傳
- 觸發時機：開啟 App、完成一輪練習、網路恢復（`online` 事件）、App 進入背景（`visibilitychange`，盡力而為）、App 開啟期間每 5 分鐘
- 上傳成功後才標記 `syncedAt`；若上傳成功但標記失敗而重傳，產生的重複紀錄會在合併時依 `uuid` 去除，不影響正確性

**下載（雲端 → 本機）**
- 本機記錄 `lastPulledAt` = **上次下載到的 chunk 中最大的 `createdAt`**（伺服器時間），不使用本機時鐘，避免時鐘誤差造成漏抓
- 每次同步時下載 `createdAt >= lastPulledAt` 的 chunk（刻意重疊，重複紀錄以 `uuid` 去除）；自己裝置上傳的 chunk 下載後直接忽略
- 本機沒有 `lastPulledAt`（新裝置、資料被清除）時，下載全部 chunk
- 下載後以 `uuid` 與本機紀錄取聯集，再重建 `cards`：
  - 一般同步：只重建**被新紀錄影響到的卡片**（新 chunk 中出現的 `cardId`），對這些卡片重放完整歷史
  - 新裝置還原、資料修復：全量重建

**設定的同步**
- 登入後**先下載雲端設定，再允許上傳**本機設定
- 只有使用者實際修改過的 key（`updatedAt` 不為空）才上傳；新裝置的預設值不會蓋掉雲端設定

**登入後的還原**
- 登入時若本機沒有任何紀錄、雲端有資料，自動下載並顯示「已從雲端還原 N 筆紀錄」
- 本機已有未登入期間產生的紀錄時，與雲端合併，不覆蓋任何一方

**規則**
- 雲端資料只會新增，不會被本機覆蓋；空的本機不會寫入任何東西
- 「重設進度」以寫入 `cardEvents`（`reset`）實作，不刪除雲端紀錄
- 只有「刪除帳號與雲端資料」會刪除雲端資料，執行前需輸入確認

**同步狀態顯示**
- 設定頁顯示：登入帳號、上次同步時間、待上傳筆數
- 超過 3 天未同步（例如一直離線或登入失效）時，首頁顯示提醒

### 7.6 JSON 匯出／匯入（備案）

- P1 即提供，作為 Firebase 啟用前的唯一備份方式，之後作為不依賴雲端的備案
- 匯出：透過分享面板存到「檔案」App（可存 iCloud Drive），內容為各紀錄表與設定，以 `CompressionStream` 進行 gzip 壓縮
- 匯入：以 `uuid` 取聯集合併，不直接覆蓋本機資料；依 `schemaVersion` 執行遷移函式；匯入前自動建立本機快照，可回復
- 設定：匯入時提示確認是否以檔案中的設定為準

**匯出檔格式**
```json
{
  "schemaVersion": 1,
  "appVersion": "0.1.0",
  "exportedAt": "2026-10-15T12:00:00Z",
  "deviceId": "…",
  "reviewLogs": [],
  "cardEvents": [],
  "handwritingLogs": [],
  "quizLogs": [],
  "contentReports": [],
  "settings": {}
}
```

### 7.7 已知風險與 P0 驗證

| 風險 | 驗證／對策 |
|---|---|
| 登入狀態在 iOS 主畫面 App 中能否長期維持 | P0：登入後關閉 App，隔天再開，確認仍維持登入 |
| Google 登入在主畫面 App 中的相容性（彈出視窗、`signInWithRedirect` 受第三方儲存限制影響） | P0 驗證；不穩定則只提供電子郵件登入 |
| 離線期間的紀錄能否在恢復網路後正確上傳 | P0：飛航模式下練習，恢復網路後確認上傳 |
| Cloudflare Pages 預覽部署的子網域未列入授權網域 | P0 確認；必要時只在正式網域測試登入 |
| 免費額度 | 紀錄打包上傳；個人使用量遠低於每日 5 萬次讀取、2 萬次寫入 |
| 依賴單一外部服務 | 保留 JSON 匯出；資料格式不綁定 Firebase |

## 11. 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| 刪除主畫面圖示即刪除所有資料；Safari 與主畫面 App 儲存空間分開 | 進度遺失 | 首次開啟引導先加入主畫面；設定頁明確警告；P1b 提供 JSON 匯出；P1.5 起自動同步到雲端 |
| iOS 系統清除 PWA 資料（儲存空間不足等） | 進度遺失 | 自動同步、登入後還原、申請持久儲存 `navigator.storage.persist()` |
| 本機資料遺失後覆蓋雲端 | 雲端資料也遺失 | 雲端紀錄只增不改，安全規則禁止更新（見 7.4、7.5） |
| Firebase 登入在 iOS 主畫面 App 不穩 | 無法同步 | 預設使用電子郵件登入；P0 先驗證；備案為匯出到「檔案」 |
| Firestore 安全規則寫錯 | 資料外洩或被他人修改 | 以 Firebase Emulator 撰寫規則測試 |
| 超過 Firebase 免費額度 | 同步暫停 | 紀錄打包成 chunk 上傳，降低讀寫次數 |
| 長時間未開 App 或離線 | 紀錄未上傳 | 開 App 即同步；超過 3 天未同步時提醒 |
| 手寫比對門檻不準 | 誤判，使用體驗差 | P0 原型驗證；調校模式收集樣本；回歸測試 |
| iOS 手勢干擾書寫 | 手寫體驗不佳 | 畫布留邊距、停用選取與長按、實機測試 |
| 每日複習量累積過多 | 做不完而放棄 | 新卡上限、每日目標、複習卡過多時自動暫停新卡；「標記已會」預設暫停排程而非排入複習 |
| 無法在 Windows 上除錯 iPhone Safari | 問題難以重現與定位 | P0 即做 App 內除錯面板 |
| 內容建置耗時（含全部中文翻譯） | 進度停滯 | 先做 N5/N4；腳本 + AI 初稿 + 抽查；邊用邊修 |
| TTS 誤讀漢字 | 學到錯誤讀音 | 單字送假名讀音；例句抽查，必要時改用音檔 |
| 新版本遲遲不生效（iOS PWA 常駐背景） | 修正無法送達 | Service Worker 更新提示 |
